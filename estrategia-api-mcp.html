API-ficação de sistemas legados
e arquitetura MCP

Como transformar sistemas fechados (desktop, ERPs antigos, painéis web sem integração) em ferramentas que agentes de IA conseguem usar — com segurança.

0.Visão geral em 30 segundos

Um agente de IA só consegue agir sobre o que tem “porta de entrada”. Sistema legado não tem. O jogo é: criar uma porta (API), padronizá-la para a IA (MCP) e ensinar o agente a usá-la bem (Skill).

1 · API

O quê: interface programática do sistema.
Resolve: “como falo com esse software?”

2 · MCP

O quê: protocolo aberto que expõe a API como tools para a IA.
Resolve: “como qualquer agente usa isso sem integração sob medida?”

3 · Skill

O quê: instruções em Markdown (SKILL.md) com contexto e regras.
Resolve: “quando e como o agente deve usar a ferramenta?”

1.As rotas para sistemas sem API

O material original trazia três rotas (A, B, C). Mantive as três, corrigi pontos imprecisos e acrescentei duas que faltavam (D e E).

Rota A Conexão direta ao banco de dados — a mais rápida

Como funciona: uma camada de API fica na frente do banco (PostgreSQL, MySQL, SQL Server, Oracle) e expõe tabelas/consultas como endpoints REST. Ferramentas como PostgREST, Hasura, Directus ou Prisma geram isso quase automaticamente.

Quando usar: você tem acesso legítimo ao banco e o esquema é estável.

⚠ Ajuste em relação ao originalO texto chama de “API fantasma” e fala em “leitura e escrita seguras”. Na prática, escrever direto no banco de um sistema legado pula as regras de negócio (validações, triggers, cálculos que só existem na aplicação) e pode corromper dados ou violar o suporte do fornecedor. Regra de ouro: comece só-leitura (usuário com SELECT, de preferência numa réplica) e só libere escrita por procedimentos controlados.
Rota B Automação de navegador / RPA web — para painéis web fechados

Como funciona: um robô controla um navegador (Playwright, Puppeteer, Selenium) e executa o que um humano faria: login, navegar, extrair dados, preencher formulários. Cada rotina vira um endpoint.

Quando usar: o sistema só existe como site/painel e não há API nem banco acessível.

⚠ Ajuste em relação ao originalApify não é um navegador simulado: é uma plataforma para hospedar e agendar esses robôs. Além disso, esta rota é frágil — mudou o layout, quebrou. Cheque também os Termos de Uso do sistema (automatizar pode ser proibido) e a LGPD se houver dado pessoal.
Rota C Webhooks e filas intermediárias (no-code)

Como funciona: n8n, Make ou Zapier recebem arquivos (Excel, PDF, e-mail, relatórios exportados), extraem e estruturam em JSON e entregam via webhook quando a IA pedir.

Quando usar: o sistema só “cospe” relatórios ou e-mails e você não precisa de tempo real.

Dica: valide o JSON de saída com um esquema (JSON Schema); extração de PDF por IA erra — registre o que foi extraído.

Rota D · nova RPA de desktop / Computer Use

O título do material cita softwares desktop, mas nenhuma rota cobria isso. Para programas Windows sem banco nem web, existem ferramentas de RPA (UiPath, Power Automate Desktop, AutoHotkey, pywinauto) ou agentes com “uso do computador”. É a opção mais lenta e frágil — último recurso.

Rota E · nova Integração oficial ou exportação nativa

Antes de qualquer gambiarra: o sistema tem API paga, módulo de integração, exportação agendada (CSV/XML), ODBC ou webhook escondido nas configurações? Pergunte ao fornecedor. É a rota mais estável e, muitas vezes, a mais barata.

4.O combo: API + MCP + Skill

API

Fundação de conectividade. Determinística, testável sem IA.

MCP

Protocolo aberto (criado pela Anthropic e hoje usado em todo o ecossistema) que descreve ferramentas, recursos e prompts de forma que qualquer cliente compatível entenda.

Skill

Arquivo SKILL.md com o “manual do analista”: quando acionar a ferramenta, em que ordem, o que nunca fazer, como formatar a resposta.

Analogia para o grupoAPI = a tomada na parede. MCP = o padrão do plugue. Skill = o manual de instruções do aparelho. Sem o manual, o agente liga o forno com a porta aberta.

Exemplo de Skill

---
name: consulta-pedidos
description: Use quando o usuário perguntar sobre status, valor ou
  histórico de pedidos de clientes no ERP.
---
# Consulta de pedidos
1. Sempre chame `buscar_cliente` antes de `listar_pedidos`.
2. Nunca chame `cancelar_pedido` sem confirmação explícita do usuário.
3. Valores em R$ com duas casas decimais; datas em dd/mm/aaaa.
4. Se a ferramenta retornar erro 429, aguarde e informe o usuário.

5.MCP em 2026: o que mudou

O MCP evolui rápido. Pontos úteis para quem vai construir agora (conforme a revisão 2026-07-28 da especificação):

  • Transporte: use Streamable HTTP para servidores remotos (o antigo HTTP+SSE está deprecated) e stdio para servidores locais.
  • Stateless: a revisão remove sessões de nível de protocolo (Mcp-Session-Id) e o handshake initialize; cada requisição carrega versão e capacidades. Isso facilita escalar atrás de load balancers.
  • Descoberta: novo método server/discover.
  • Cache: listas de tools passam a trazer ttlMs e cacheScope; devolva as tools em ordem determinística.
  • Autorização: baseada em OAuth 2.1; registro dinâmico de cliente (DCR) foi marcado como deprecated em favor de Client ID Metadata Documents.
  • Deprecados: Roots, Sampling e Logging de protocolo.
AtençãoSDKs e clientes nem sempre acompanham a revisão mais nova no mesmo dia. Confira a versão de protocolo suportada pelo SDK e pelo cliente antes de projetar.

6.Mão na massa: da API ao servidor MCP

Se a sua API já tem especificação OpenAPI (3.0/3.1), dá para gerar um MCP quase automaticamente com o FastMCP (Python):

import httpx
from fastmcp import FastMCP

client = httpx.AsyncClient(
    base_url="https://api.minhaempresa.com",
    headers={"Authorization": "Bearer <TOKEN>"},   # use variável de ambiente!
)
spec = httpx.get("https://api.minhaempresa.com/openapi.json").json()

mcp = FastMCP.from_openapi(openapi_spec=spec, client=client, name="ERP")

if __name__ == "__main__":
    mcp.run()
Não exponha tudoGerar um tool por endpoint cria dezenas de ferramentas e confunde o modelo (e aumenta o custo de tokens). Filtre: exponha só os endpoints necessários, escreva descrições claras e prefira poucas ferramentas orientadas a tarefas (“consultar_status_pedido”) em vez de espelhar o CRUD inteiro.

Boas práticas de desenho de tools

  • Nome curto e descritivo; descrição dizendo quando usar e quando não usar.
  • Parâmetros tipados e validados (JSON Schema); respostas enxutas (o modelo não precisa de 200 colunas).
  • Separe ferramentas de leitura e de escrita; marque as destrutivas e exija confirmação humana.
  • Mensagens de erro úteis para o agente se corrigir (“cliente_id deve ter 8 dígitos”).

Plano de projeto em 5 etapas

  1. Mapear: quais 3–5 tarefas realmente valem automatizar?
  2. Escolher a rota (seção 2) e montar a API só-leitura.
  3. Subir o MCP local (stdio) e testar com o MCP Inspector.
  4. Escrever a Skill e testar com casos reais, inclusive perguntas ambíguas.
  5. Endurecer: autenticação, logs, limites, só então liberar escrita e acesso remoto.

7.Segurança — a parte que o original não tinha

Ao ligar IA a um sistema real, o risco muda de “resposta errada” para “ação errada”. Principais ameaças (veja OWASP – MCP Security):

Prompt injection

Texto malicioso dentro de um dado (e-mail, campo de cliente, PDF) que instrui o agente a fazer algo não autorizado. Trate todo dado vindo do sistema como não confiável.

Tool poisoning

Instruções escondidas na descrição de uma ferramenta de terceiros. Use só servidores MCP auditados e fixe versões.

Excesso de privilégio

Token com acesso a tudo. Se o agente for enganado, o estrago é total.

Vazamento de dados

Dados pessoais enviados ao modelo/logs. Aplique mascaramento e a LGPD (base legal, minimização).

Defesas mínimas

  • Menor privilégio: credencial só com o que cada tool precisa; banco em modo só-leitura.
  • Humano no circuito para ações destrutivas ou financeiras.
  • Autenticação em todo servidor remoto (OAuth 2.1); segredos em cofre/variáveis de ambiente, nunca no código ou na Skill.
  • Validação de entradas e saídas; limites de taxa e de tamanho.
  • Auditoria: registre quem/qual agente chamou o quê, com quais parâmetros.
  • Ambiente de teste (cópia dos dados) antes de apontar para produção.

8.Checklist antes de colocar em produção

  • Perguntei ao fornecedor se existe API/exportação oficial?
  • Li os termos de uso do sistema sobre automação/acesso a dados?
  • Credenciais com menor privilégio e guardadas fora do código?
  • Ferramentas de escrita separadas, com confirmação humana?
  • Descrições das tools claras; poucas tools, orientadas a tarefas?
  • Skill escrita e testada com casos reais e casos de borda?
  • Logs e alertas funcionando; plano de revogar acesso rapidamente?
  • Dados pessoais tratados conforme a LGPD?
  • Plano para quando o sistema legado mudar (testes automáticos na API)?

Glossário rápido

APIInterface para um programa falar com outro.
REST / OpenAPIEstilo de API web / formato padrão (ex-Swagger) que descreve seus endpoints.
MCPModel Context Protocol: padrão aberto para expor ferramentas e dados a agentes de IA.
ToolFunção que o agente pode chamar via MCP.
Cliente/Host MCPAplicativo que usa servidores MCP (Claude Code, Cursor, Cline…).
SkillPacote de instruções (SKILL.md) que orienta o comportamento do agente.
RPAAutomação robótica de processos: robô que imita cliques e digitação.
WebhookChamada HTTP automática disparada por um evento.
Prompt injectionInstrução maliciosa escondida em dados que a IA lê.
